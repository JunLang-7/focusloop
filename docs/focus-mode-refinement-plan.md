# 专注模式改进计划

## 目标

让 Focus 工作区里的当前任务、完整计划、恢复卡和侧栏在宽/窄窗口中保持清晰、可操作。计划面板应是工作区自然流的一部分；计时器、学习状态和持久化边界在界面与说明中保持一致。

## 模型协作与执行顺序

1. **Sol 审查**：审阅需求、源码行为和布局实现，给出可复现的问题与验收标准；检查修订是否覆盖问题，复核最终浏览器结果。
2. **Luna 执行**：根据审查结果修改布局/功能，运行本地构建和类型检查，配合真实 Playwright 验证。
3. **Sol 最终复核**：审查 Playwright 场景及多视口证据，核对没有回归后，由主代理确认最终状态并更新本计划。

## 布局与行为要求

- 计划面板在专注工作区自然文档流中，展开和收起使用相同的居中宽度：`min(100%, 860px)`。
- 展开长计划时，滚动发生在计划自身的限高区域；不固定为覆盖当前任务的底部浮层，不切换页面 padding/height 模式，也不因展开计划而强制滚动页面。
- 计划开合状态初始为关闭。按开关切换；Escape、点击计划外部、开始任务或完成任务都会关闭计划。求助选择器打开时 Escape 优先关闭选择器，计划仍保持原状态。
- 恢复卡是专注页唯一底部通知。它在应用内以非模态行呈现；展开时 Escape 只折叠通知并阻止该按键继续传播，通知已折叠时 Escape 才交给页面处理当前求助选择器或计划面板。
- 有恢复卡时，专注任务区保留独立滚动和尺寸观察，任务控件不被通知遮挡。
- 任务标题可换行，操作按钮可在任务行内换行或堆叠。保留语义化任务列表、可键盘操作的排序把手及移动位置播报；时间线仅为辅助信息。
- 视口宽度不超过 480 CSS px 时，计划改用自然流的垂直任务列表，标题完整换行、操作按钮位于下一行；桌面/较宽视口用等高行的计划列表，估时写在行内。指针排序根据已渲染行的矩形位置计算落点，适应窄屏不等高任务行。
- 页头在纵向空间紧张时不收缩；内容滚动条槽位保持稳定，避免滚动条出现/消失时让布局横向跳动。
- 宽/窄视口均不得出现横向页面溢出、内容裁切、控件重叠或任务/计划/通知之间遮挡。

## 验收清单

- 完整操作专注功能：从课程会话进入；启动、暂停、继续、加一分钟及到时处理；完成并继续任务；提交文字答案/查看导师多轮交流；答题并查看正误和解释；附带文件并检查抽取结果；打开/取消卡住求助；接受并结束建议；处理恢复卡；展开/收起、排序和启动计划任务；检查无活动会话及全部完成状态。
- 验证个人计时阶段和领域 `LearningState` 是两套状态；确认个人倒计时只在渲染进程内存中保留、路由切换不重置，会话/任务切换重置；确认学习事实和任务顺序仍通过主进程/事件记录持久化。
- 验证计划开合宽度相同且不超过 860 CSS px；窄屏不超过可用宽度；计划长内容只在自身区域滚动；展开时不强制页面滚动。
- 在宽屏验证按比例高度的时间线；在不超过 480 CSS px 的视口验证自然流垂直列表、完整多行标题、按钮下一行及按渲染行矩形工作的拖动排序。
- 验证窄屏页头不会被纵向压缩，且滚动条槽位稳定、不造成内容水平跳动。
- 验证计划在 Escape、外部点击、开始/完成任务时关闭；求助选择器优先响应 Escape；通知展开时 Escape 先折叠，下一次才交给页面。
- 在多个代表性视口检查：无水平页面溢出、裁切、任务操作重叠、恢复卡遮挡；标题可读；任务排序和关闭行为可用键盘完成。
- 真实 Playwright 功能审计与多视口证据均通过后，Sol 复核并由主代理更新结果。单元测试、构建或类型检查不能替代浏览器验收。
- 文档中的每项行为以当前源码和实际浏览器结果为依据；最终审计完成前保持本计划未完成状态。
