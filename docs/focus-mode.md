# 专注模式：操作手册与设计说明

本文说明桌面版 Focus 工作区的操作方式、状态含义和实现边界。专注页不是单独的番茄钟：它把课程任务、学习状态、短时个人计时、导师交互、恢复卡和任务计划放在同一工作区。它们由不同状态所有者管理，不能互相替代。实现依据见 [architecture.md](architecture.md)；计划面板的布局目标和验收进度见[专注模式改进计划](focus-mode-refinement-plan.md)。

## 开始一次专注

1. 从课程启动一个学习会话，应用进入该会话的 Focus 工作区。页头显示课程名、当前学习状态、轻噪音开关和结束会话操作。
2. 查看“下一小步”的任务标题、说明和预计时长。选择“先做 3 分钟”后，任务成为当前任务，个人专注倒计时开始。
3. 按任务说明学习。任务可包含选择题或文字作答；具体交互由当前任务提供的内容决定。
4. 需要调整节奏时，暂停、继续或加一分钟。时间到后，倒计时显示结束状态，可用“+1 分钟”继续。
5. 完成任务后进入下一步；全部任务完成时，页面显示完成状态。也可在计划列表中直接开始某个待做任务。

如果当前没有活动会话，专注页会提示先从课程开始，并提供课程浏览入口。结束会话使用页头“结束会话”按钮；离开专注页只会离开该路由，不等于结束会话。

## 工作区各区域

- **页头**：课程标题、当前学习状态、轻噪音开关和结束会话。轻噪音是应用生成的声音，可随时开关；它不改变计时或学习状态。
- **进度条**：展示课程步骤进展和已记录的会话时长。这里的时长遵从事件记录的可信时段规则，和下方个人倒计时不是同一个数值。
- **当前任务**：显示任务标题、说明、类型/预计时间，以及该任务提供的学习练习。未开始时显示下一任务；完成后显示下一步或全部完成状态。
- **个人计时器**：围绕当前任务的短时承诺，可暂停、继续和加一分钟。该时钟不是课程任务的预计时长，也不决定学习状态机中的 `FOCUSED` 或 `INTERRUPTED`。
- **任务计划**：展开后查看剩余任务及估算时间，选择计划行中的“开始”切换到该任务，并调整任务顺序。
- **导师与恢复卡**：导师建议嵌在当前任务控制区；恢复卡只在需要恢复先前位置时出现在专注页底部通知行。

## 个人倒计时状态与规则

专注计时器有四种本地阶段：

| 阶段                | 含义和操作                                               |
| ------------------- | -------------------------------------------------------- |
| `ready`（待开始）   | 当前任务还没有开始短时承诺。开始按钮启动默认 3 分钟。    |
| `active`（进行中）  | 倒计时运行。可暂停、加一分钟、完成任务或请求帮助。       |
| `paused`（已暂停）  | 剩余时间冻结。继续从剩余时间计时；加一分钟后仍保持暂停。 |
| `expired`（已到时） | 剩余时间为零。加一分钟会把计时器重新打开并开始计时。     |

计时器以结束时间计算正在运行的倒计时，因此界面延迟刷新时会按当前时间追上；暂停时先结算已流逝时间，再固定剩余时长；继续时根据剩余时长生成新的结束时间。增加一分钟不抹去已用时间。计时数字采用 `分:秒` 格式，圆环进度限制在 0 到 100%。

计时器属于渲染进程中的 `FocusTimerService`。在同一个应用运行期间切换路由时，当前承诺会保留；会话或当前任务改变时，计时器会重置为新任务的三分钟待开始状态。应用重启后不会恢复个人倒计时，因为它目前只存在内存里，没有写入 SQLite。任务完成并进入下一任务也会因任务所有者改变而重置。

学习引擎的 `LearningState` 是另一套状态：`READY`、`INITIATION_FRICTION`、`FOCUSED`、`CONFUSED`、`OVERLOADED`、`DISTRACTED`、`INTERRUPTED` 和 `RESUMING`。它由领域事件和时间评估驱动。例如，暂停个人时钟不会自动变成 `INTERRUPTED`；计时器到时也不会结束会话。对应转换和干预优先级见 [架构说明的状态引擎](architecture.md#the-state-engine)。

## 任务练习、导师与卡住求助

如果任务带有选择题，选择答案后按“检查答案”提交；页面显示答对/答错状态，答错时也显示正确选项和解释。若当前任务有文字作答框，按提示写下自己的理解或过程，再按“让导师看看”提交。可按当前练习类型附带文件；界面会说明文件是直接读入、经 OCR 识别、内容截断，还是不支持/无法读取。识别出的内容应先核对再使用。导师回答显示在当前步骤的控制区内，不会覆盖任务。

按“卡住了”会打开原因选择器，选择“我不知道从哪开始”“读了但没看懂”“一次太多了”“做了但做错了”“本来会的，想不起来了”或“没力气了”，让策略按原因和当前学习状态决定是否给提示、例子、问题、休息或更小任务建议。“不想说”仍会发送一次不带具体原因的求助事件；只有按 Escape 关闭选择器才是不提交。若策略因干预预算等规则返回不操作，界面可能保持原样。更小/拆分任务建议需要用户确认后才应用；它是当前会话任务的派生改写，不覆盖课程原始内容。已接受的 BREAK 休息会暂停个人专注时钟，用户继续后才恢复。

练习按当前任务提供的形式操作：

1. **选择题**：选择一个选项，再按“检查答案”。结果区域显示答对/答错和题目解释；选项标记会指出正确项，选错时也保留你选中的错误项。
2. **文字作答**：在输入框写下自己的理解或过程，再按“让导师看看”。输入框有字符长度限制；提交后导师面板会显示回复，可展开继续多轮交流。文字答案会先记录为当前任务答案，再发送给导师检查。
3. **附带文件**：按“附带文件”选择本地材料。应用会在本机读取支持的文字，或对图片执行 OCR，并把提取结果放进同一个输入框供你检查和编辑；超出输入框容量的部分会被截断并提示。取消选择不会更改答案；不支持、过大、无法读取或没有文字的文件会显示对应提示。

不同任务可能只提供其中一种或几种练习。选择题结果不会代替完成任务；文字答案也会随当前任务变化而清除。

原因选择器打开时键盘焦点进入带标签的选项组。按 Escape 可关闭且不提交，并把焦点还给触发按钮。“不想说”则是一次真实的无原因求助事件，并非取消。卡片或建议消失时，若键盘焦点原本位于被移除控件，焦点会交还给仍有效的工作区控件。

## 恢复卡通知

专注页底部的通知槽**只承载恢复卡**，用于会话中断后帮助找到离开前的位置。只有当前会话存在待处理恢复卡时它才出现。它不是普通导师建议，也不是计时到时提示：导师建议直接显示在步骤控制区，到时通过计时器旁的“+1 分钟”处理。

通知行是应用内的非模态界面，不是操作系统通知，不请求系统通知权限，也不会在出现时自动抢焦点或限制 Tab。按“显示通知/收起通知”可折叠或展开；在展开的通知内按 Escape 会先折叠通知并停止本次按键继续传播。通知已经折叠时，Escape 会继续交给专注页：若求助选择器打开则先关闭选择器，否则关闭打开的计划面板。折叠只改变呈现，不接受、拒绝或关闭恢复决定。折叠状态在同一会话的路由重挂载期间保留，新会话重新展开。恢复卡决策移除当前卡片后，如焦点原本位于被移除的控件，键盘焦点会移回专注工作区地标。更多产品决策和验证范围见[通知设计说明](focus-notice.md)。

## 计划面板与任务排序

点击“查看完整计划”展开计划，点击“收起计划”关闭。计划展示待做任务、任务估时和剩余时间估算；在任务行选择“开始”即可切换当前任务，并自动关闭计划。按 Escape 或点击计划以外的位置也会关闭计划；Escape 会把焦点还给计划开关。若求助选择器打开，Escape 优先关闭选择器，计划保持原状。拖动任务行，或聚焦行内的排序把手并用键盘操作，可调整剩余任务顺序：Enter/空格向下移动，Shift+Enter/空格向上移动，上下方向键也可移动。界面会播报移动后的序号。当前正在执行的任务不属于待做列表。

排序是当前会话的决定，由 `TASKS_REORDERED` 事件记录；开始新会话会清空该次排序，不会修改课程的默认任务顺序。窗口宽度不超过 480 CSS px 时，计划以自然流的垂直任务列表显示，标题可以完整换行，开始等操作按钮另起一行；较宽视口用等高行的计划列表，估计时长写在每一行上，而不是靠区块高度表示。指针排序按实际渲染出的任务行矩形计算位置，因此窄屏行高随标题换行变化时仍可拖动排序；键盘排序把手在两种布局中都保留。

布局规则是计划始终位于工作区自然文档流中，展开和收起使用同一个居中的列宽，最大 860 CSS px，窄屏时不超过可用宽度。长计划在计划面板自身限高区域内滚动；打开计划不应把页面强制滚到计划处，也不应切换页面 padding/height 模式。恢复卡通知独立占据底部行；通知出现时，专注任务区保留自己的滚动和尺寸观察。页头不参与窄屏纵向压缩，专注内容使用稳定的滚动条槽位，避免滚动条出现时造成水平位移。最终布局验收状态记录在[改进计划](focus-mode-refinement-plan.md)。

## 侧栏、导航与键盘

专注期间，自动侧栏策略会收起活动侧栏，让工作区保持安静；使用应用提供的浮动侧栏按钮可临时召回侧栏。离开专注页后，这种临时召回会回到自动策略，用户明确收起的状态继续保持收起。侧栏显示与否不更改会话或任务。

计划排序、原因选择器和通知均提供键盘操作。Escape 先取消正在进行的排序拖动；否则关闭求助选择器，再关闭计划面板。展开的恢复通知会优先响应 Escape 并折叠，下一次 Escape 才交给页面。关闭选择器或计划时会归还焦点。所有按钮仍可通过 Tab 访问。响应式布局允许内容纵向滚动，但不得出现水平页面溢出、任务标题裁切、控件重叠或被通知遮挡。

## 数据和持久化边界

| 数据                                                                   | 所有者                                              | 边界                                                               |
| ---------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------ |
| 课程、会话、当前任务、完成记录、任务排序事件、中断检查点和已确认的建议 | Electron 主进程引擎及 SQLite，经校验 IPC 提供给界面 | 应用数据持久化；学习视图可由事件和领域记录重建。                   |
| 学习状态与干预决策                                                     | 纯领域 reducer、策略和主进程 tick                   | 由事件/时间评估推导；不是视觉控件状态，也不是个人计时器阶段。      |
| 当前任务的个人倒计时                                                   | 渲染进程根级 `FocusTimerService`                    | 仅当前应用进程内存；路由切换保留，重启不恢复，会话/任务切换重置。  |
| 计划开合、求助选择器、当前输入与练习结果呈现                           | Focus 页面/组件                                     | 界面状态；计划开合不是持久化偏好。排序等学习决定另以领域事件记录。 |
| 恢复通知折叠                                                           | Focus 通知组件                                      | 同一会话内的渲染进程状态；新会话默认展开，不是持久化用户设置。     |

渲染器不直接读写数据库，持久化的学习事实经 IPC 交给主进程。会话时长显示使用 dashboard 的可信记录时段规则：静默只记到 idle 阈值，未经观察的沉默不算作离开，也不把整段会话墙钟时间都算作专注。专注页进度时长与个人倒计时因此可能同时显示不同时间，含义也不同。
